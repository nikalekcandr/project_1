# mmsim — симулятор маркет-мейкинга Авельянеды–Стойкова на данных Мосбиржи

Бэктестер стратегий пассивного маркет-мейкинга на исторических данных
Московской биржи (акции TQBR, фьючерсы FORTS). Котировки строятся по модели
Авельянеды–Стойкова (2008) и её развитию — модели Геана–Лелаля–Фернандес-Тапиа
(GLFT). Параметры модели калибруются по рыночным данным без заглядывания в будущее.

Что есть в проекте:

- **Модели:** Авельянеда–Стойков с конечным горизонтом (до конца сессии), скользящим
  и бесконечным горизонтом; GLFT в асимптотической замкнутой форме и точное решение
  через матричную экспоненту с жёстким лимитом позиции; бенчмарки: симметричная
  стратегия из статьи и фиксированный спред.
- **Данные:** клиент MOEX ISS (свечи, лента сделок с признаком инициатора, лот, шаг
  цены, стоимость шага фьючерса) с постраничной загрузкой и дисковым кэшем; загрузка
  CSV (экспорт Финама, формат ISS, произвольные колонки); синтетический генератор
  ленты «в стиле» SBER для работы офлайн.
- **Калибровка:** σ по приращениям цены внутри сессии, A и k — по интенсивности
  «доставания» цены до глубины δ; walk-forward по предыдущим дням, опционально
  EWMA-оценка σ внутри дня.
- **Исполнение:** три модели — по свечам, по ленте сделок, по пуассоновской
  интенсивности (как в статье). Шаг цены, лоты, post-only, лимит позиции, комиссии
  maker/taker (включая ребейты), принудительное закрытие позиции к концу сессии.
- **Аналитика:** разложение P&L (спред / позиция / закрытие / комиссии), Шарп,
  просадка, захват спреда, markout (adverse selection), статистика позиции;
  HTML-отчёты с графиками, сравнение стратегий, перебор параметров.
- **Воспроизведение статьи:** Монте-Карло эксперимент Авельянеды–Стойкова (2008).
- **Тесты:** 44 теста (`pytest`), включая проверку отсутствия заглядывания в будущее
  и сходимости денежного учёта с журналом сделок.

## Модель

Mid-цена — арифметическое броуновское движение `dS = σ dW`. Лимитная заявка на
расстоянии δ от mid исполняется с интенсивностью `λ(δ) = A·exp(−kδ)`. Маркет-мейкер
максимизирует `E[−exp(−γ·(X_T + q_T·S_T))]`, где X — деньги, q — позиция.

**Авельянеда–Стойков, конечный горизонт** (`strategy.name = "as"`):

```
резервационная цена   r = s − q·γ·σ²·(T − t)
оптимальный спред     δᵃ + δᵇ = γ·σ²·(T − t) + (2/γ)·ln(1 + γ/k)
котировки             bid = r − спред/2,  ask = r + спред/2
```

Резервационная цена смещается против позиции: с длинной позицией котировки
сдвигаются вниз, чтобы продавать охотнее и покупать реже. Параметр `horizon`:

| значение   | T − t                                                        |
|------------|--------------------------------------------------------------|
| `session`  | время до конца торговой сессии (как в статье)                |
| `rolling`  | постоянное окно `horizon_seconds`                            |
| `infinite` | стационарный вариант статьи с ограничением `|q| ≤ q_max` (ω = ½γ²σ²(q_max+1)²) |

`as_symmetric` — симметричная стратегия из статьи: тот же спред, но вокруг mid,
без учёта позиции. Сравнение с ней показывает вклад управления позицией.

**GLFT** (`glft`, `glft_exact`) — та же постановка с жёстким лимитом `|q| ≤ Q`:

```
асимптотика (τ → ∞):
δᵇ = (1/γ)·ln(1 + γ/k) + (2q + 1)/2 · σ·√( γ/(2kA) · (1 + γ/k)^(1 + k/γ) )
δᵃ = (1/γ)·ln(1 + γ/k) − (2q − 1)/2 · σ·√( … )

точное решение: v(t) = exp(−M·(T − t))·1,  M[q,q] = (k/2)γσ²q²,  M[q,q±1] = −A(1 + γ/k)^−(1+k/γ)
δᵇ = (1/k)·ln(v_q / v_{q+1}) + (1/γ)·ln(1 + γ/k),   δᵃ = (1/k)·ln(v_q / v_{q−1}) + (1/γ)·ln(1 + γ/k)
```

Точное решение при большом горизонте сходится к асимптотике; это проверяется в тестах.

### Единицы

| величина | единица | комментарий |
|---|---|---|
| s, δ, r | руб. (пункты для фьючерсов) | |
| σ | руб./√с | σ за сессию = σ·√(длительность в секундах) |
| τ = T − t | секунды | |
| A | 1/с | интенсивность исполнений при δ = 0 |
| k | 1/руб. | 1/k — характерная глубина |
| q | размеры котировки | позиция в лотах / `order_size` |
| γ | 1/(руб. · ед. q) | неприятие риска; подбирается перебором (`mmsim sweep`) |

Для SBER (цена около 300 руб., σ за сессию около 5 руб.) при горизонте «до конца
сессии» смещение резервационной цены на единицу позиции в начале дня равно
`γ·σ²·τ ≈ γ·25` руб., поэтому разумные значения γ — порядка 0.001–0.05.

## Калибровка σ, A, k

- **σ:** среднеквадратичное приращение цены закрытия соседних баров внутри сессии
  (переходы через ночь исключены), делённое на длительность бара.
- **A, k:** котировка выставляется от цены закрытия предыдущего бара (ref). Для
  глубины δ считаем долю баров P̂(δ), в которых high − ref ≥ δ (и ref − low ≥ δ). При
  пуассоновском потоке `P = 1 − exp(−λ(δ)·Δt)`, откуда `λ(δ) = −ln(1 − P̂)/Δt`. Затем
  МНК по `ln λ = ln A − k·δ`. Критерий «цена дошла до δ» совпадает со свечной моделью
  исполнения, поэтому параметры согласованы с симулятором.
- **walk-forward:** параметры каждой сессии оцениваются по `window_days` предыдущих
  торговых дней. Первая сессия без истории — разогрев, в ней не торгуем. При загрузке
  с MOEX история до `data.start` подгружается автоматически.
- `full_sample` — оценка по всей выборке (удобно для исследования, но с заглядыванием
  в будущее); `fixed` — значения задаются вручную в `[calibration]`.
- `sigma_ewma_halflife > 0` — адаптивная σ внутри дня (EWMA по барам).

`mmsim calibrate` печатает эмпирическую таблицу λ(δ) и строит график подгонки.

## Данные

### MOEX ISS (`source = "moex"`)

Используются бесплатные эндпоинты информационно-статистического сервера биржи
(`https://iss.moex.com/iss/...`):

| что | эндпоинт |
|---|---|
| параметры инструмента (LOTSIZE, MINSTEP, STEPPRICE) | `engines/{engine}/markets/{market}/boards/{board}/securities/{secid}.json` |
| свечи 1 / 10 / 60 минут, день | `.../securities/{secid}/candles.json?from=&till=&interval=` |
| лента сделок текущей сессии с BUYSELL | `.../securities/{secid}/trades.json` |

Свечи грузятся постранично (параметр `start`) по дням и кэшируются в `data/cache`
(только завершённые дни). Объём свечей приводится к штукам автоматически (проверка
по обороту `value ≈ volume · price`). Без подписки данные текущего дня ISS отдаёт с
задержкой; историческая лента сделок в бесплатном доступе отсутствует, поэтому для
истории основной режим — минутные свечи, а режим `trades` — для ленты текущего дня
(`data.trades = true`) или тиков из CSV.

Акции: `engine = "stock"`, `market = "shares"`, `board = "TQBR"`.
Фьючерсы: `engine = "futures"`, `market = "forts"`, `board = "RFUD"` (пример —
`configs/si_futures_glft.toml`); стоимость шага цены берётся из ISS.

### CSV (`source = "csv"`)

```toml
[data]
source = "csv"
secid = "SBER"
candles_csv = "data/SBER_1min.csv"   # Финам: <DATE>,<TIME>,<OPEN>,<HIGH>,<LOW>,<CLOSE>,<VOL>
trades_csv = "data/SBER_ticks.csv"   # Финам: <DATE>,<TIME>,<LAST>,<VOL>,<ID>,<OPER>
csv_bar_seconds = 60
```

Также читаются формат ISS (`begin,open,close,high,low,value,volume`) и произвольный
CSV с колонками `time, open, high, low, close, volume` или `time, price, qty, side`.
Если сторона сделки неизвестна, она восстанавливается по tick rule.

### Синтетика (`source = "synthetic"`)

Генератор ленты «в стиле» SBER: цена около 300 руб., шаг 0,01, лот 10, годовая
волатильность 28 %, U-образная внутридневная активность, дробление заявок (серии
сделок одной стороны), влияние потока на цену, скачки и ночные гэпы. Это **не
реальные данные** — они нужны для демонстрации, тестов и проверки модели в
контролируемых условиях.

## Моделирование исполнения

В публичных данных нет стакана и очереди заявок, поэтому исполнение пассивных
заявок приближается по сделкам. Котировки шага i считаются только по информации до
начала шага (цена закрытия предыдущего бара), так что заглядывания в будущее нет.

| `fill_model` | правило исполнения нашей покупки по цене b |
|---|---|
| `candle` | low < b (цену проторговали насквозь) → исполнено; low = b → исполнено с вероятностью `touch_fill_prob` (мы в очереди на уровне). Объём ограничен долей `max_participation` объёма бара |
| `trades` | продажи-инициаторы по цене < b (или = b с вероятностью очереди); объём не больше объёма этих сделок. Перекотировка каждые `requote_seconds` |
| `intensity` | с вероятностью `1 − exp(−A·e^{−kδ}·Δt)`, как в статье; цены — из данных |

Модель `intensity` не учитывает adverse selection (исполнение не связано с
последующим движением цены), поэтому она оптимистична. `candle` и `trades` его
учитывают: нас исполняют именно тогда, когда цена идёт против нас. Сравнение одной
стратегии в разных моделях исполнения показывает, сколько P&L «съедает» отбор.

Прочие правила:

- **post-only:** bid не выше `ref − market_half_spread_ticks`, ask не ниже
  `ref + market_half_spread_ticks` (округление к шагу цены), иначе заявка была бы
  агрессивной;
- **лимит позиции** `max_inventory` (лоты): сторона, которая увеличила бы позицию
  сверх лимита, не котируется;
- **комиссии** в б.п. от оборота: `maker_fee_bps` (отрицательное значение — ребейт
  по программе маркет-мейкинга), `taker_fee_bps`. Подставьте свой тариф брокера и биржи;
- **закрытие позиции** к концу сессии по рынку: цена закрытия бара ± полуспред ±
  `liquidation_slippage_ticks`, комиссия taker.

## Метрики

| метрика | смысл |
|---|---|
| P&L: спред | Σ side·(mid − цена)·объём по пассивным сделкам — заработок на спреде |
| P&L: позиция | переоценка удерживаемой позиции; сюда попадают потери от adverse selection |
| P&L: закрытие | издержки принудительного закрытия относительно mid |
| комиссии | все комиссии; итог = спред + позиция + закрытие − комиссии |
| Шарп | по дневному P&L, годовой (×√252) |
| захват спреда | средний выигрыш на лот относительно mid, в тиках |
| markout h | side·(цена через h шагов − цена сделки) в тиках; отрицательный — нас «переехали» |
| позиция | средняя |q|, ст. откл., максимум, доля времени на лимите |

Отчёт `run` сохраняет `report.html`, графики PNG, `steps.csv` (каждый шаг: котировки,
позиция, деньги, σ/A/k), `fills.csv`, `daily.csv`, `params.csv`, `metrics.json`.

## Конфигурация

Полный пример с комментариями — `configs/sber_as.toml`. Разделы:

- `[data]` — источник, тикер, режим торгов, даты, интервал свечей, пути к CSV;
- `[instrument]` — переопределение `lot_size`, `tick_size`, `step_price`;
- `[sessions]` — `use = ["main"]` (также `morning`, `evening`); границы сессий можно
  переопределить: `custom = { main = ["10:00", "18:40"] }`;
- `[strategy]` — `name`, `gamma`, `order_size`, `horizon`, `horizon_seconds`,
  `half_spread_ticks`, `skew_ticks_per_unit`, `terminal_penalty`;
- `[execution]` — модель исполнения, комиссии, лимиты, post-only, закрытие позиции;
- `[calibration]` — `mode`, `window_days`, `sigma_ewma_halflife`, фиксированные `sigma`/`A`/`k`;
- `[report]` — `out_dir`, `plot_day`.

## Python API

```python
from mmsim import MoexISS, AvellanedaStoikov, ExecutionConfig, CalibrationConfig, run_backtest
from mmsim.report import write_report

data = MoexISS().load("SBER", "2025-09-01", "2025-09-30", interval=1)
res = run_backtest(
    data,
    AvellanedaStoikov(gamma=0.01, horizon="session"),
    ExecutionConfig(fill_model="candle", max_inventory=10, maker_fee_bps=1.0),
    CalibrationConfig(mode="walk_forward", window_days=5),
    trade_start="2025-09-08",
)
print(res.metrics["pnl_total"], res.metrics["sharpe_annual"])
write_report(res, "reports/sber")
```

Своя стратегия — наследник `mmsim.strategies.Strategy` с методом
`quote(state) -> Quote`; в `state` есть mid, τ, позиция, σ, A, k, шаг цены.
Полный пример — `examples/quickstart.py`.

## Ограничения

- Нет стакана: позиция в очереди, скрытая ликвидность и реакция рынка на наши
  заявки не моделируются. Параметры `touch_fill_prob` и `max_participation`
  задают допущения явно: проверяйте чувствительность результата к ним.
- Mid оценивается ценой последней сделки (закрытия бара), в неё входит bid-ask
  bounce. Калибровка k делается в той же системе отсчёта, что и исполнение.
- На минутных свечах котировки обновляются раз в минуту: это консервативно для
  HFT-стратегии, но исключает заглядывание внутрь бара.
- Аукционы открытия и закрытия, клиринг и ценовые лимиты не моделируются; по
  умолчанию торгуется только основная сессия и позиция закрывается к её концу.
- Высокий Шарп на коротком периоде ненадёжен: смотрите на число дней, разложение
  P&L и markout.
